# Making visual storyboard panels

Read when creating a new storyboard, unless the user explicitly requested a written-only
plan. The goal is an inspectable image for each essential panel in the requested scope.
Visual polish can be rough; legible action, spatial continuity, and reveal order matter more.

## Choose a creation route

Use the user's chosen image maker if the host can access it and its use is authorized.
Otherwise use an available built-in or connected image generator, drawing capability, or
browser-controlled image website. Select by ability to create and retrieve images, preserve
the intended aspect ratio and references, and allow inspection. A provider preference is
not a reason to stop if that route is unavailable and another authorized route can do the
work, unless the user made the chosen route exclusive. Do not claim an inaccessible
service was used, assume a login, or incur an unapproved
external charge. The Skill does not require a specific model, site, API, or credential.

## Render the sequence

1. Lock the panel list and the scene's fixed facts: panel ID, visible instant, frame,
   geography, recurring appearance, prop state, hidden information, and aspect ratio.
   Use supplied design references. If visual identity is underdefined, record a concise
   consistent design description before generating; do not invent a new story beat.
2. Make one self-contained image instruction per panel. Describe what the viewer should
   see *now*: composition, camera side/height, pose, object placement, expression, and
   what must remain out of view. Put motion between panels in the panel card, not as two
   incompatible poses in one image. Translate panel IDs into output names or a manifest;
   the generator need not draw the IDs inside the frame.
3. Generate every essential panel in the agreed scope. Where supported, use approved
   character, location, prop, style, or prior-panel images as references or edit inputs.
   Where unsupported, repeat stable visible traits and test continuity manually. A
   contact sheet can aid sequence review, but it does not replace individual inspectable
   panels. Keep extra variants separate from the selected sequence.
4. Inspect each returned image at its intended viewing size. Compare it with its card and
   adjacent panels: character/prop identity, hand and holder, screen direction, geography,
   eyeline, concealed information, readable action, and visual style. Correct significant
   errors through a focused edit or regeneration when the route supports it. Keep the
   planned story fact when a render disagrees; record unresolved deviations instead of
   quietly rewriting the plan to fit the image.
5. Deliver the images in panel order with IDs, source shot, short caption, and status.
   Save project-bound files in the user's requested destination or an appropriate workspace
   location. An inline image is a visual deliverable if the host exposes it there; a web
   preview alone is not a saved file. State which panels were inspected and which remain
   missing, uninspected, or inconsistent.

If no authorized image route works, supply the ordered panel cards and self-contained
generation instructions for each essential panel. Label them **unrendered** and name the
specific blocker. If a route fails partway, keep the successful images and identify the
unrendered remainder; do not call the visual board complete. Actual timed playback is a
separate animatic deliverable.
