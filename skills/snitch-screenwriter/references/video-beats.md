# Extract and reuse video beats

Load this Reference when the user wants to understand a reference video's structure or use
its beats for a new story. A beat is a meaningful change in action, knowledge, expectation,
emotion, or argument. It is not automatically a shot, cut, line, or fixed time interval.

## Establish what can be inspected

Read the supplied file or link, requested source span, and desired deliverable: breakdown,
reusable outline, or adaptation. For adaptation, use the new premise or subject, target
length, audience, medium, and protected choices. Ask only for missing information that
blocks that work; extracting beats does not require a new premise.

Use available video inspection capabilities to examine the actual picture and, when
available, sound. If direct inspection is unavailable, use accessible timestamped frames,
clips, audio, or transcripts and describe their limits. A transcript can support spoken
argument and verbal reveals; it cannot establish silent action, expression, visual reveals,
music, or pauses it does not record. Stills cannot verify motion or continuous performance.
If nothing usable is accessible, ask for an accessible file or transcript and mark media
inspection as a Skip. Do not substitute a remembered plot or page description for viewing.

Assign a neutral source ID such as `V01` and retain its file/link locator in a source ledger
so timestamps are checkable. Keep analysis prose about events and functions, without naming
creators or presenting their reputation as evidence. Record the source version, duration
and how established, requested span, inspected intervals, modality for each interval, and
gaps. Separate source time from time relative to an excerpt; record its offset if known.
Use `HH:MM:SS` elapsed source timestamps, or explicitly approximate ranges if precision is
unavailable. Never invent exact timings from an untimed transcript. Derived percentages
need a known span and a stated denominator (full source or selected excerpt).

## Inspect at the scale of the material

- For a short clip, trace the requested span, including the opening and ending. Revisit
  turns, quiet action, and setup/payoff pairs; dialogue alone may miss the central beat.
- For longer material, establish sections or sequences, then inspect them in manageable
  contiguous batches. Maintain one ledger with stable section and beat IDs, absolute source
  times, carried questions, setup/payoff links, and unresolved gaps. Revisit adjoining
  intervals where a beat crosses a batch boundary; merge duplicates without losing IDs.
- Use chapters, transcripts, or sparse frames for navigation when helpful. Sampling alone
  yields a provisional map of the inspected material, not an exhaustive whole-video map.
  Check gaps before claiming full coverage. If access or host limits prevent completion,
  deliver the covered portion with exact gaps and the next span to inspect. An hour-long
  video is not reduced to its opening because the first batch filled the context.

There is no fixed runtime ceiling or mandatory beat count. Use a sequence overview with
nested beats for a long work; a compact beat table may suffice for two or five minutes.
Keep long-form state in project notes when authorized or in an explicit continuation ledger.

## Build the source beat map

Record each meaningful change using this shape, splitting tables if readability needs it:

`beat ID / section | source in–out | observed event and evidence modality | before → after |
story function (interpretation) | setup/payoff or dependency IDs`

Paraphrase events concisely. Attach an asset ID and time range to each observation; cite
transcript lines or frame timestamps when those are the actual evidence. Mark uncertain
boundaries and competing interpretations instead of manufacturing precision.

Name functions in terms that fit the video: a hook opens a question, a promise sets an
expectation, an attempt meets resistance, evidence revises a claim, a demonstration tests
an explanation, a reversal changes the stakes, a payoff resolves an earlier setup. Quiet
observation or a repeated image can change emotional context. Do not force an interview,
tutorial, or observational work into a hero's journey or a prescribed act template.

Distinguish what is shown from why it might work. If the user calls the video successful,
record that as supplied context unless performance evidence is available. Views, likes,
or retention data do not by themselves establish that a particular beat caused success.
Keep timing-aligned metrics, structural observations, and causal hypotheses separate;
never promise the same results from using the structure.

## Make the structure reusable

Extract a second layer that removes source-specific people, dialogue, imagery, and plot
devices while preserving the ordered functions, dependencies, escalation, and release.
For example: an apparent shortcut offers relief → a failed attempt exposes its hidden
cost → an earlier overlooked constraint enables a different solution. Explain what each
beat needs from the preceding beats and what it makes possible later.

When adaptation is requested, map source beat IDs to new beats:

`source beat IDs | reusable function | new event or argument | setup/payoff link |
estimated target duration | preserved, combined, expanded, or omitted and why`

Use the user's new subject and constraints to invent new events and expression. Reusing
the same ordered functions is supported; simply renaming the source's characters and
repeating its scenes is not the default adaptation. If the user is revising their own
material or requests a closer adaptation, honor that scope rather than automatically
stripping its protected elements. A breakdown alone does not authorize a new script.

Treat relative source positions and durations as descriptive starting points, not rules.
For a shorter target, compress or combine supporting beats while preserving what earns
the payoff. For a longer target, develop attempts, evidence, consequences, and responses
rather than padding holds or multiplying every duration. Show the resulting target timing
budget, including transitions and holds, and label it estimated. Flag conflicts with a
protected beat or runtime instead of quietly cutting it. New scenes receive their own
scene IDs linked to the source beat IDs; source timestamps never become measured timing
for the new script.

## Deliver and verify

Return the source/coverage ledger, beat map, reusable structure, and, only when requested,
adaptation outline or pages. For large sources, give an overview followed by section maps;
preserve the detailed ledger across batches. Check that times are within the source span,
beat order is consistent, duplicated overlaps are resolved, and setup/payoff references
resolve. Account for interstitial or uninspected spans rather than inventing beats to fill
every second. Check that proposed durations fit the target and dependencies survive any
compression. End with what was inspected, what remains a Skip and how to unblock it, and
which timing or effectiveness claims are estimates or hypotheses.
