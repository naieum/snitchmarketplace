## How references load

References are NOT pre-loaded by the skill. The agent reads them on-demand based on the conditions in the "When surfaced" column. This keeps token cost manageable; an audit running only Quick Audit (13 cats) typically loads 4-6 references, not all 35.

## Adding a new reference

When a new reference doc is added, append a row to this index with the same three-column structure (Reference / Purpose / When surfaced). The "When surfaced" column is the load-bearing field; without it, the agent doesn't know when to load the reference.

## Reference vs category file

References are CROSS-CUTTING (apply across many cats or workflow steps). Category files are PER-CATEGORY (apply to one cat's detection / fix logic). When a piece of guidance applies to a single cat, it lives in the cat file. When it applies across cats, it lives in a reference. New cross-cutting docs go in `references/`; new cat-specific guidance extends an existing cat file.
