## CATEGORY 2: Sitemap.xml

`sitemap.xml` is how you tell crawlers "here are all the URLs I want indexed, and here's metadata about each (lastmod, changefreq, priority)." Without one, bots discover URLs by following links, slower, less complete. With a broken one (404, malformed XML, listing dead URLs), you waste crawl budget and signal incompetence.

### Evidence required (do not skip)

**Source mode, required tool calls:**

1. `Glob` for `**/sitemap.xml`, `**/sitemap.{ts,js}`, `**/sitemap-*.xml`. Quote each match.
2. For framework-generated sitemaps (Next.js `app/sitemap.ts`, TanStack `src/routes/sitemap[.]xml.ts`, Astro `src/pages/sitemap.xml.ts`): `Read` the generator file, quote the URL list it produces. If the list comes from a CMS / DB call, quote the data-fetch logic.
3. For static `public/sitemap.xml`: `Read` the file, parse as XML. Quote parse errors literally.
4. For "sitemap declared in robots.txt but not present" findings: load the robots.txt content (cross-reference Cat 1's evidence) and verify each `Sitemap:` directive resolves to an actual file in the project.

**Crawl mode, required tool calls:**

1. `Fetch` `{origin}/sitemap.xml`. Quote the response status + first 500 chars of body.
2. If the response is HTML or 404, that IS the finding, no sitemap served.
3. Parse the XML. Count `<url>` entries. For "URLs in sitemap return 404" findings, sample up to 10 URLs from the sitemap, fetch each, quote their response status.

### Forbidden claims

- "The sitemap probably doesn't include all pages." Compare the sitemap URL count to a route enumeration (Glob in source mode, internal-link-graph crawl in crawl mode). State the delta.
- "The sitemap may be malformed." Parse it. Either it parses or it doesn't. Quote the parse error.
- "The lastmod dates are probably stale." Sample at least 5 URLs and quote their `<lastmod>` values vs the file system mtime (source mode) or vs the page's actual last-modified header (crawl mode).

### Detection

#### Source mode

- **Static**: `public/sitemap.xml`, `static/sitemap.xml`, root-level `sitemap.xml`.
- **Next.js App Router**: `app/sitemap.ts` exporting `MetadataRoute.Sitemap`.
- **Next.js Pages Router**: usually `public/sitemap.xml` or via `next-sitemap` build script.
- **Astro**: `@astrojs/sitemap` integration in `astro.config.{js,ts}`, OR a manual `src/pages/sitemap.xml.ts` route.
- **TanStack Start**: usually `src/routes/sitemap[.]xml.ts` route handler.
- **WordPress**: dynamically generated by Yoast / RankMath / WordPress core; check plugin settings (DB, not source).
- **Shopify**: auto-generated, usually `/sitemap.xml` and per-collection sitemaps. Theme cannot disable.
- **Static site generators (Hugo / Jekyll / Eleventy)**: built-in sitemap generation, usually produces `sitemap.xml` in output dir.

#### Crawl mode

`Fetch` `{origin}/sitemap.xml`. If 404, also try `{origin}/sitemap_index.xml`, `{origin}/sitemap-index.xml`, and check robots.txt for declared sitemap paths.

### What to Search For

Literal strings in source / generators:

- `<sitemapindex` (sitemap-of-sitemaps)
- `<urlset` (single sitemap)
- `MetadataRoute.Sitemap` (Next.js)
- `next-sitemap` config / build script
- `@astrojs/sitemap` import
- Generator functions returning arrays of `{ url, lastModified, changeFrequency, priority }`

### Actually Hurts SEO

- **No sitemap at all.**
  Evidence required: confirmed source-mode + crawl-mode absence. Quote `404 Not Found` from `/sitemap.xml` plus the "no source generator found" enumeration.
- **Sitemap returns 5xx.**
  Evidence required: fetched response status. Quote it.
- **Malformed XML in sitemap.**
  Evidence required: parse error message + the offending line.
- **URLs in sitemap return 404 / 410.**
  Evidence required: sampled URLs, each with quoted response status.
- **URLs in sitemap that are `noindex`'d or canonicalized away.**
  Evidence required: the URL from the sitemap AND the `<meta name="robots" content="noindex">` from that URL's response (or the `<link rel="canonical">` pointing elsewhere).
- **Sitemap doesn't include some indexable pages** (incomplete inventory).
  Evidence required: list of URLs missing from sitemap (Glob in source mode, OR crawl results in crawl mode) compared to sitemap contents. State the delta concretely.
- **`lastmod` dates that never change** (frozen at sitemap generation).
  Evidence required: sample of `<lastmod>` values across multiple URLs that all match the same date. The pattern is the finding.
- **Sitemap declares `priority` and `changefreq` for everything as `1.0` and `daily`.**
  Evidence required: quoted XML showing the uniform values. (Note: Google ignores priority/changefreq, flag as Low; the finding is "wasted XML" not "lost ranking.")
- **No sitemap declared in robots.txt** when one exists.
  Evidence required: robots.txt content (no `Sitemap:` directive) + sitemap.xml content (proves it exists).

### NOT a Problem

- A sitemap with `<priority>` and `<changefreq>` set to default values. Google ignores both fields entirely. Don't flag.
- A small static site with no sitemap, Google can crawl the whole site from the homepage in seconds.
- A sitemap-index file (`sitemap_index.xml`) pointing at multiple per-section sitemaps. Standard pattern; correct for large sites.
- Trailing-slash inconsistency between sitemap and canonical IF the canonical and sitemap agree per-URL (each URL has its own canonical and the sitemap entry matches that canonical).

### Context Check

1. Is the site small enough that no sitemap is fine? Under ~50 pages with clean internal linking, a sitemap is nice-to-have, not essential. Lower severity for tiny sites.
2. Is the framework auto-generating from real data? Quote the generator's data source. A sitemap that returns `[]` because the data fetch failed silently is a Critical bug.
3. Does the site have separate sitemaps for content types (posts, products, videos, news)? Don't flag the "main" sitemap as incomplete if other sitemap URLs cover the gap.
4. Is the sitemap UTF-8? Sitemaps must be UTF-8 per the spec; non-UTF-8 sitemaps are rejected.
5. Is the sitemap >50,000 URLs OR >50MB uncompressed? That exceeds Google's per-sitemap limit. The fix is sitemap-index splitting.

### Reference

Sitemaps protocol: https://www.sitemaps.org/protocol.html

Google's sitemap documentation: https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview

**Severity tagging:**
- No sitemap on a multi-page site → High.
- Sitemap returns 404/5xx → Critical.
- Malformed XML → Critical.
- URLs in sitemap return 404 → High (proportional: 5+ broken URLs = High; <5 = Medium).
- Noindex'd / canonicalized URLs in sitemap → Medium.
- Frozen lastmod dates → Low.
- Priority/changefreq on everything → Low (or skip with note).
- No sitemap declared in robots.txt → Low.

**Fix voice:** `solutions-architect` (primary) | `analytics-engineer` (backup, when the sitemap is a measurement / discovery problem rather than an architecture one).

Read `souls/solutions-architect.json` before writing the Fix. Sitemaps are URL inventory; SA's voice is "declare the system's surface area cleanly so other systems can consume it."

Worked fix example:

> Generate the sitemap from the same source-of-truth that produces the routes. If routes come from a CMS, the sitemap is a transformation of that CMS query. Don't maintain two lists.
>
> ```ts
> // app/sitemap.ts
> export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
>   const posts = await getAllPosts();  // same call the route uses
>   return [
>     { url: 'https://example.com/', lastModified: new Date() },
>     ...posts.map(p => ({
>       url: `https://example.com/blog/${p.slug}`,
>       lastModified: p.updatedAt,
>     })),
>   ];
> }
> ```
>
> Add the `Sitemap: https://example.com/sitemap.xml` line to robots.txt explicitly. Then verify by fetching the sitemap and feeding it to Google Search Console's "Sitemaps" submission once.
